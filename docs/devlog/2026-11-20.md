## 失敗：止めたはずの壊す確かめが裏で動き続け、別の作業場所の E2E と 4173 番のサーバーを借り合った

- 起きたこと：NORI-87 の壊す確かめ（`sound.ts` をわざと壊して E2E を流すスクリプト、9 通り）を、バックグラウンドの作業を止める道具で止めたつもりだった。実際はスクリプトの続き（1 通りごとの `npx playwright test`）が動き続け、17:45〜17:54 に M1〜M6 を流していた
- 影響：
  - NORI-65 の E2E が、NORI-87 の作業場所のサーバー（`reuseExistingServer`。すでに 4173 番で動いているサーバーを借りる設定）を借り、違う作りを確かめた。壊す確かめが 1 通り終わってサーバーを止めると、NORI-65 の E2E は「サーバーにつながらない」で 49 件・27 件落ちた
  - `privacy.spec.ts` の 1 件の失敗を「PC が重かった」と書いていた。確かめていない推測だった（PR の説明から直した）
  - NORI-87 の `sound.ts` が、壊したまま残っていた（M7 の途中で止まった。写しから戻して差分 0 を確かめた）
- 見つけ方：4173 番を使っているプロセスのコマンドの行（`Get-NetTCPConnection` → `Win32_Process`）で、作業場所が NORI-87 だとわかった。起動の時刻（17:52:01）と壊す確かめの記録のファイルの時刻を並べて、まだ動いていると気づいた
- 学び：
  - バックグラウンドの作業を止めても、その子のプロセスが止まったとは限らない。止めたら、プロセスの一覧と、そのスクリプトの記録のファイルの時刻で確かめる
  - 作業場所が 2 つ以上あると、E2E はポートを借り合う。E2E を流す前に 4173 番が空いていることを確かめる（壊す確かめのスクリプトには足した。手元の E2E 全体には仕組みがない → 引き継ぎに課題の候補として書く）
- 車載の例え：同じ CAN のバス（ポート）に、止めたはずの古い試験機（ほかの作業場所のサーバー）がつながったままで、新しい試験の結果に古い機械の返事が混じった

## 失敗：レビューのあとの直しを、オーナーにコードの差分で判断してもらおうとした

- 起きたこと：PR #117 で、レビューのあとの直し（be4ee68・8937534）のコミットのリンクを渡して「見てください」と頼んだ。オーナーの答えは「コードの差分では判断できない」
- 直したこと：直しごとに「何が変わるか・直しをわざと戻すと落ちるテスト」の表を作った。作るために直し 3〜5 を 1 つずつ戻すと、**3 つとも単体テストが 1 件も落ちなかった**。3 と 5 にテストを足した（cddd1c6）。4 は動きが同じでテストで違いが出せない（`res.json()` の例外で同じ道に入る）
- 決まり：CLAUDE.md を PR #118 で変えた（直しごとの証拠の表でオーナーが判断する）。Hook で守るのは NORI-83（スプリント5の予定）
- 学び：テストが緑なのは「直しを守っている」証拠にならない。直しを戻して落ちるかで確かめる（車載の例：故障注入試験。正常系が通っても、注入した故障を検出できるかは別に試す）

## 学んだこと 3 行

1. テストが緑でも、直しを守っているとは限らない。直しをわざと戻して落ちるかで確かめる（故障注入試験と同じ。11/20、直し 3 つが戻しても通った）
2. 確認を頼むときは、コードの差分でなく「何が変わるか・戻すと落ちるテスト」の表と画面で判断してもらう（オーナーが決めた。PR #118）
3. 手元の E2E を流す前に 4173 番が空いているかを確かめ、止めた作業は本当に止まったかをプロセスと記録の時刻で見る（止めたはずの壊す確かめが裏で動き、別の作業場所のサーバーを借りていた）

## 失敗

- `npm install` が npm 内部のエラー（`Cannot read properties of null (reading 'edgesOut')`）で止まった。vitest 5 の任意の peer 依存の解決で起きる npm の不具合。`--legacy-peer-deps` で入れ、`npm ci` が通ることを確認した
- `npm view --before` は日付で絞り込まれず、2週間以内の版が出てきた。公開日（`npm view <pkg> time`）を自分で確かめて版を選び直した
- 自分が立ち上げた古い preview サーバーがポート 4173 に残り、直した設定が効いていないように見えた。`netstat` でプロセスを確かめて止めた
- `gh repo create` は auto モードの判定で止められた（外部へのアップロードにあたるため）→ オーナーに依頼
- Jira の CSV 取り込みで、ポイントが **Story point estimate**（`customfield_10016`）に入り、ボードが見る **Story Points**（`customfield_10034`）は空だった。原因は、Story Points のグローバルなコンテキストが「Atlassian 管理」で、NORI では無視されていたこと。NORI 専用のコンテキストと画面への追加で解決
- MCP で Jira に書き込むまでに、**4か所の許可**が必要だった：① Claude Code の deny、② claude.ai のコネクターのツール権限、③ Atlassian 管理画面の Write、④ Search（課題の作成が内部で検索を使う）。②〜④はコネクターのつなぎ直しで反映。1つずつしか分からず、オーナーに何度も作業を頼むことになった
- スプリントの作成・開始は、MCP では「削除と同じ扱い」（終了が取り消せないため）。削除系はブロックの方針なので、画面でオーナーが実施
- 時刻を確かめずに「22時ごろ」と書いた（実際は23時）。スプリントの開始時刻も 23:02 になっていた
- GitHub リポジトリを作り PR #1 を出したら、CI の E2E が失敗した。ログを見ると CI はソフトウェア描画（SwiftShader）で約3fps。1フレームの刻みの上限（5回）でゲーム内の時間が約1/4しか進まず、12秒で36.5mだった。距離の判定を「ゲーム内で進んだ時間」基準に直した

## 学び

- Hook のテストを書こうとしたら、テスト用のコマンド自体を Hook が止めた。**仕組みが本当に動いている証拠**になった。秘密情報らしい文字列は、テストの中で実行時に組み立てる
- 「文書の数値 = 設定の数値」をテストにすると、文書の書き方（数を先頭に書く）までそろう。仕様書を機械で読める形にするのは、車載の要求管理と同じ考え方
- 推測で直さず、ブラウザのログ（404）を見たら原因は1分で分かった。10月のルール「実際の値を確かめる」が効いた
- CI の約3fps は、性能の低いタブレットで起こりうる姿でもある。S28（性能）で、影・建物数・解像度を下げる「軽量モード」を検討する
- 権限のエラーは「どの許可が足りないか」をそのまま返してくれた（`Insufficient scope: ... write:jira:agent-interface`）。推測せずにエラーの文を読めば、次に何を頼めばよいかが分かる。最初に「必要な許可の一覧」を調べてから頼めば、往復を減らせた
- CSV 取り込みは画面の設定を気にせず値を入れるが、API（MCP）は**作成画面にないフィールドに値を入れられない**。同じ「課題を作る」でも、経路によって前提が違う

## 学び

- テストで API を先に決めておくと、実装は1回で通る（当たり判定の 11 件）。前の晩に「設計メモ」を handoff に書いたのも効いた
- 「触れているか」を衝突の数だけで決めると、壁と平行に走るときに途切れて、何度も減速する。**余白つきの重なり**で判定すると安定する。ルールの表にも数値で書いた（`PHYSICS.touchMargin`）
- Blender MCP は、公式ページを読むだけでは分からないことが多かった。**ソースを読んで**、`_for_cli` の道具が隔離の外（オーナーのユーザー）で Blender を起動すると分かった。仕事でも、AI の道具を入れる前に「どのプロセスが、どのユーザーで、何を実行するか」を図にすると、穴が見える
- 公式ページの取得は拒否されたが、git でソースを取ってくれば読めた。読めない経路があっても、別の正しい経路を探す
- 一致テストが「文書 → 設定」だけだと、設定にだけ数値を足しても気づかない。**両方向**にして初めて「一致している」と言える
- 隔離の作業フォルダを、リポジトリの中（オーナーのフォルダの中）に置く計画だったが、それでは専用ユーザーから届かない。**権限の境界をまたぐ場所**に作業フォルダを置く必要がある

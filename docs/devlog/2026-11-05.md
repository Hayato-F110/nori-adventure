## 失敗

- `npm install` が npm 内部のエラー（`Cannot read properties of null (reading 'edgesOut')`）で止まった。vitest 5 の任意の peer 依存の解決で起きる npm の不具合。`--legacy-peer-deps` で入れ、`npm ci` が通ることを確認した
- `npm view --before` は日付で絞り込まれず、2週間以内の版が出てきた。公開日（`npm view <pkg> time`）を自分で確かめて版を選び直した
- 自分が立ち上げた古い preview サーバーがポート 4173 に残り、直した設定が効いていないように見えた。`netstat` でプロセスを確かめて止めた
- `gh repo create` は auto モードの判定で止められた（外部へのアップロードにあたるため）→ オーナーに依頼
- GitHub リポジトリを作り PR #1 を出したら、CI の E2E が失敗した。ログを見ると CI はソフトウェア描画（SwiftShader）で約3fps。1フレームの刻みの上限（5回）でゲーム内の時間が約1/4しか進まず、12秒で36.5mだった。距離の判定を「ゲーム内で進んだ時間」基準に直した

## 学び

- Hook のテストを書こうとしたら、テスト用のコマンド自体を Hook が止めた。**仕組みが本当に動いている証拠**になった。秘密情報らしい文字列は、テストの中で実行時に組み立てる
- 「文書の数値 = 設定の数値」をテストにすると、文書の書き方（数を先頭に書く）までそろう。仕様書を機械で読める形にするのは、車載の要求管理と同じ考え方
- 推測で直さず、ブラウザのログ（404）を見たら原因は1分で分かった。10月のルール「実際の値を確かめる」が効いた
- CI の約3fps は、性能の低いタブレットで起こりうる姿でもある。S28（性能）で、影・建物数・解像度を下げる「軽量モード」を検討する

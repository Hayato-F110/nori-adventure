## 調べて分かったこと（一覧の前提）

1. 今の Hook `approval-jira`（`.claude/hooks/approval-jira.mjs`、Stop の Hook）は、返答に「承認のお願い」があり、かつ「課題」の列がある表（刈り取りの表）があるときだけ、表の課題ごとに同じ回で Jira を読んだかを確かめる。表がない承認のお願いは、何も確かめずに通す（`issuesInHarvestTables` が空を返す）。2026-11-16、NORI-76 の承認のお願い（ハッシュ値 c630c0f5）がこれで通った
2. 一覧の表のハッシュ値は 16 進 8 文字。承認のお願いでは「ハッシュ値 xxxxxxxx」と書く（`tests/docs/testPlans.test.ts` のメッセージと同じ書き方）
3. Hook の会話の記録（transcript）は JSON の行の並び。スキルを呼ぶと `tool_use` の `name` が `Skill`、`input.skill` がスキルの名前になる。コミットは Bash の `tool_use` の `input.command` に `git commit` が入る
4. `gh pr create` を呼ぶ時点では、PR の差分は「今のブランチ」と `origin/main` の差（`git diff --name-only origin/main...HEAD`）で読める。Hook は PreToolUse で、Bash の `tool_input.command` を読む（`guard-long-foreground.mjs` と同じ形）
5. コードを変えるとみなすフォルダは、CLAUDE.md の決まりと同じ `src/`・`e2e/`・`tests/`・`tools/`・`.claude/hooks/`

## 調べて分かったこと（一覧の前提）

1. 今の Hook `approval-jira`（`.claude/hooks/approval-jira.mjs`、Stop の Hook）は、返答に「承認のお願い」があり、かつ「課題」の列がある表があるときだけ、表の課題ごとに同じ回で Jira を読んだかを確かめる。表がない承認のお願いは、何も確かめずに通す（`issuesInHarvestTables` が空を返す）。2026-11-16、NORI-76 の承認のお願い（ハッシュ値 c630c0f5）がこれで通った
2. 返答にハッシュ値を書く決まりはない（CLAUDE.md がハッシュ値を書けとしているのは、一覧の中の初見レビュー・承認の行だけ。R1-78-3）。そのため、一覧の承認のお願いと見る印は、ハッシュ値だけでなく「`test-plans/NORI-` の文字」「テストの一覧」の語も使う
3. 刈り取りの表の形は、見出しの最初の列が「項目」で、「課題」「結果」の列がある（最初の列が「項目」かは `tests/docs/testPlans.test.ts` と同じ。「課題」「結果」の列は `harvest-before-done.mjs` とも同じ。R1-78-5・R2-78-7）
4. Hook の会話の記録（transcript）は JSON の行の並び。スキルを呼ぶと `tool_use` の `name` が `Skill`、`input.skill` がスキルの名前になる（プラグインのスキルは `名前:スキル` の形。R1-78-9）。コミットは Bash・PowerShell の `tool_use` の `input.command` に入る
5. このプロジェクトでは、Bash と PowerShell の両方からコマンドを流す。今ある PreToolUse の Hook は `Bash|PowerShell` に登録している（`.claude/settings.json`、`guard-long-foreground.mjs`。R1-78-1）
6. 作業は `.claude/worktrees/<名前>` で行い、`cd <worktree> && gh pr create` の形が多い。PR の差分は「PR のブランチ」と `origin/main` の差（`git diff --name-only origin/main...<branch>`）で読む。場所は、コマンドの先頭の `cd X &&`・`cd X;`・`Set-Location X;`・`Push-Location X;`（PowerShell。R2-78-5）、`git -C`、入力の `cwd` の順に決め、`--head <branch>` があればそのブランチを使う（R1-78-2）
7. 会話の記録は、記録のファイル全体を見る（`stop_hook_summary` 以降の回だけではない）。記録の各行には、その時の作業の場所 `cwd` がある。コミットとレビューは、その場所（コミットは前提 6 と同じ決め方、レビューは記録の行の `cwd`）が PR のブランチの場所と同じものだけを数える（1 つのセッションで複数のブランチを扱うため。R2-78-3・R2-78-4）
8. コードを変えるとみなすフォルダは、CLAUDE.md の決まりと同じ `src/`・`e2e/`・`tests/`・`tools/`・`.claude/hooks/`

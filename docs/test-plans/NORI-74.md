## 調べて分かったこと（一覧の前提）

1. すれ違う電車の線路の上の距離は、刻みだけで決まる式（`passingTrainDistance(線路の長さ, tick)`＝`STAGE2.passingStart − STAGE2.passingSpeed × tick × SIM.fixedDt` を線路の長さで回り込ませる。`src/core/stage2Layout.ts`）。描く位置は `src/render/stage2View.ts` の `placePassing` が決める。`placePassing` は `stage2View.ts` の中の `offsetPoint` と `rightOf`（進む向きの右）で置く。横の位置（x, z）は `offsetOnTrack(線路, 距離, −STAGE2.passingOffset)`（`stage2Layout.ts`）と同じ式だが、**コードは別**（同じ式が2か所にある）。高さだけレールの上 `RAIL_TOP` を足す（2回目の初見レビュー R2-74-1）
2. 描くときの刻みは、前の刻みとの間を補った**小数**（`previous.tick + (current.tick − previous.tick) × alpha`。`src/stage2Main.ts`）。早送りでは1コマの時間がちょうど刻みの数の分なので、補う割合 alpha はほぼ 0（丸めの分だけ）になり、描いた刻みは `current.tick − 1` 前後になる（`src/core/loop.ts`）。テストでは、描いた刻みが整数であることや `current.tick − 1` と等しいことは確かめない（R2-74-5）。今の読み取り口 `window.__nori.passingTrain()` は位置（x, y, z）だけを返し、どの刻みの位置かが分からない。そのため、`placePassing` が実際に使った刻みと線路の上の距離を、読むときに計算し直さずにそのまま返す
3. 列車を選ぶまで時間は進まない（`ready()` が選ぶ前に刻み 0 を確かめている）。選んだあとは、運転役が1つ目の駅（150 m）まで走って止まり、そのあとは入力 0（`installFirstStationDriver`。上の表示のテストと同じ）
4. 11/13 の E2E の総点検（`docs/test-plans/e2e-audit-2026-11-13.md`）は、この場所を「B（実際の速さが要る）」に分け、「すれ違う電車が動くこと以外」と添えていた。電車が動くことを確かめる所は A（運転役＋早送り）にするべきだった
5. 「線路の左」を確かめている今のテスト（`tests/render/stage2View.test.ts`「すれ違う電車は、時刻どおりに…」）は、期待値も実装と同じ `offsetOnTrack(…, −passingOffset)` で作る。`offsetOnTrack` の左右の約束が逆になっても、テストも逆になって通る（初見レビュー 74-1）
6. すれ違う電車は、ふつうの電車の GLB が読めたら箱から差しかわる（`src/stage2Main.ts` の `usePassingModel`）。この差しかえを確かめるテストはない（`e2e/vehicle-models.spec.ts` はモデルの一覧の画面で読むだけで、ゲームを始めない）

## 範囲の外（理由）

- 景色のテストのほかの `waitForTimeout`（`stage2.spec.ts` の見た目のテストの 90 刻み・FPS のテスト）は、総点検で仕分け済み（見た目は早送りなしで刻みを待つ、FPS は実際の速さが要る種類）
- プライバシーのページのスクリーンショット（NORI-73）は、原因が違うので別の課題
- 砂浜の幅・山の大きさと雪・雲の高さ・土手を左へ広げることを確かめるテスト（初見レビュー 74-8・74-13）。見た目だけの値で遊び方は変わらず、この課題は E2E が時間に頼るのを直すもの。設定と文書の値が一致することは `tests/config/rules-sync.test.ts` が確かめている

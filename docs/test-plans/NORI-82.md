## 調べて分かったこと（一覧の前提）

1. 公式の資料（https://code.claude.com/docs/en/hooks、2026-11-16 に読んだ）：PostToolUse の Hook は、終了コード 0 で標準出力に `{"hookSpecificOutput":{"hookEventName":"PostToolUse","additionalContext":"…"}}` を出すと、その文が道具の結果の横に入り、Claude が次に読む。オーナーの画面には出ない。道具が失敗したときは別の事象 PostToolUseFailure で、同じく `additionalContext` を使える。matcher を省くか `"*"` にすると、すべての道具が対象。文は 10,000 文字まで。命令の形でなく、事実を述べる形で書くよう書いてある
2. 今の `.claude/settings.json` の PostToolUse には、`Edit|Write|MultiEdit`（format-and-lint）と `SubagentHandback`（save-agent-report）がある。PostToolUseFailure はない
3. 今の Hook `japanese-reply`（`.claude/hooks/japanese-reply.mjs`）は、PreToolUse（道具の前の文）と Stop（この回の文章）で英語だけの行を見つけて止める。止めたことは、会話の記録（transcript。1 行が 1 つの JSON）に残る。11/16 の記録（`a3847038-….jsonl`）で確かめた形（R1-82-2）：
   - 道具の前で止めた：`type` が `user` の行の `message.content` の中の `tool_result`（`is_error: true`）の文が `PreToolUse:<道具> hook error: [node ${CLAUDE_PROJECT_DIR}/.claude/hooks/japanese-reply.mjs]: 道具を呼ぶ前に止めました…` で始まる。同じ行の `toolUseResult` にも `Error: ` から始まる写しがあり、`type` が `api-request-blob` の行にも写しが入る（R1-82-1 (a)）
   - 応答の終わりで止めた：`type` が `user` の行のメッセージが `Stop hook feedback:` で始まり、`japanese-reply.mjs]: 止めました：この回の文章に` を含む。同じことが `type` が `system` の行の `hookErrors` にも入る（R1-82-1 (b)）
   - Hook のソースを読んだ・直した道具の結果にも、同じ文がそのまま入る（R1-82-1 (c)）
4. 道具の呼び出しは 1 回の作業で数十〜数百回ある。差し込む文は毎回会話に入るので、長くすると会話の量が増える。1 回の呼び出しごとに node が 1 回立ち上がる
5. 設定（`.claude/settings.json`）が効くのは、Claude Code が読み込んだ作業場所の設定。今の会話は本体の作業場所（main）で動いているので、効き始めるのは、main にマージして本体に取り込んだあとに始めたセッションから（R1-82-9）
6. 会話の記録は、メインの会話が `~/.claude/projects/<このプロジェクト>/<セッション>.jsonl`、サブエージェントは別のファイル（`subagents/agent-*.jsonl`）（R1-82-3）

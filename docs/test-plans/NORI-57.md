## 調べて分かったこと（一覧の前提）

1. 5 つのステージとも、ゲームに渡す入力は `InputFrame`（`throttle`・`steer` の2つの数。`src/core/types.ts`）。運転役（E2E 用に入力を決める仕組み）・タッチ・ゲームパッドの入力は途中の値（64 ビットの小数）になる。記録するのは `drivenInput` を通ったあとの、ゲームに渡した値（丸めない）。運転役がいるときは `drivenInput` は運転役の入力だけを返し、キーを読まない（`src/input/testDriver.ts`）
2. 各ステージのループは別のファイル（`src/main.ts`・`src/stage2Main.ts`〜`stage5Main.ts`）にある。記録と再生は1つの部品 `src/core/replayRecorder.ts`（記録）と `src/core/replayFlow.ts`（再生の流れ）にまとめ、5 つのループはそれを呼ぶだけにする。外へ出さないことは、この2つのファイルで調べる
3. ゴールまで走る単体テスト用の運転役は、ステージ1（`tests/helpers/autopilot.ts`）・ステージ2（`tests/core/stage2.test.ts` の `driver`）・ステージ3（`tests/core/stage3.test.ts` の `circleDriver`）にある。ステージ5（`tests/core/replay.test.ts`。PR #69）はジャンプ・届ける・岩の場面まで。ステージ4はない。ステージ2・3の運転役は `tests/helpers/` に移して共有する
4. ゲームはゴールのあとも刻みを進める（入力 0。`src/core/game.ts`）。記録はゴールの刻みで止める（ルール）
5. 再生も E2E の早送り（`stepsPerFrame`）に乗せる。乗せないと CI（約 3 fps）では1コマ 5 刻みが上限で、再生がゴールの約4倍の時間かかる。1 倍の速さは単体テスト 3 で見る。固定刻みのループは1コマ 5 刻み（5/60 秒）が上限で、それを超える時間は捨てる（`src/core/loop.ts`）
6. 音：今の `createSoundCueTracker` は前のぶつかり音の刻みを持ち続け（`src/core/soundCues.ts`）、再生で刻みが 0 に戻ると引き算が負になり、再生中ずっとぶつかり音が鳴らない。`src/render/sound.ts` はゴールで `musicStopped` を true にして BGM を止め、予約（`scheduleMusic`）も止めたまま。単体テストの場所は node（画面の部品なし）なので、BGM の予約の決め方を純粋な関数に切り出して見る
7. クリアのボタンは今 3 つ（もう一回・つぎ・タイトル）で `<a href>`（ページごと移る）。ステージ5は「つぎ」を隠す（`src/render/clearFlow.ts`）。並びの `.clear` は `gap: min(24px, 3vw)`・`padding: min(18px, 2vw)`、ボタンは `width: 96px`（`--clear-button`）に内の余白 10 px・枠 5 px（`src/style.css`）。`box-sizing` の指定はないので、ボタンの外の幅は 126 px。今の `e2e/title.spec.ts` はステージ4のクリアでボタンを 3 つと見ているので、「みる」を足したら 4 つに直す
8. クリアのボタンは、実際の時間で 3 秒後に出る（`CLEAR.buttonsDelaySeconds`）。E2E では NORI-70 と同じ形（3 秒の幅を画面の更新の間隔から決める）で待つ
9. `rules-sync`（ルールの表と設定の値を比べるテスト）は、キーが1つの行を値の欄の先頭の数で比べる。ルールの行は「96 px」「600 秒」などで始め、カメラの行・狭い画面の行は1行1キーに分けた
10. E2E で再生の途中の状態を読むため、調べる口（`window.__nori`）に「再生の刻み N の状態を残す」仕組みを足す（早送りで1コマに 20 刻み進んでも飛び越さない）

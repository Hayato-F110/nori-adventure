  - PR #90（Hook だけ）の run 43843499017：E2（197 行）が 2 回続けて `frame.evaluate: Frame was detached`（237 行）
  - PR #92（文書だけ）の run 43846902634：E5「high を覚えている：ステージ3」（397 行）が 406 行で `cover.look` が `"textured"` のはずが `null`

- 一覧を変えるときは、この表を直して初見レビューを回し直し、オーナーの承認をもらう

## 調べて分かったこと（一覧の前提）

1. ステージのコードは、`src/main.ts` が `await import("./stage3Main")` などで後から読み込む（`src/main.ts:182-203`）。読み込みが終わり `startStage3` が `window.__nori` を入れるまで、`window.__nori` は undefined（`src/stage3Main.ts:200`）
2. E5（`start-cover.spec.ts:401`）と E2 の後半（293 行）の待つ条件 `window.__nori?.cover?.state !== "covered"` は、`window.__nori` が undefined のときにも成り立つ。成り立った直後の次の読み取り（404 行・296 行）で `__nori` ができていると、覆いの途中の値（`source` は作ったときに入る `"memory"`、`look` は外し始めるまで `null`。`src/render/stageCover.ts:38-47・56-61`）を読む
3. E5 の落ちた回の画面の記録（`error-context.md`）に、覆いの「よみこみちゅう」の絵が出ていた。2 と合う。ほかの落ち方（外し始めたのに `look` が `null`）は、`update` が状態と `look` を同じ呼び出しで書くので起きない（`src/render/stageCover.ts:53-69`）
   - 2026-11-17 に手元で確かめた（一時的なテスト `e2e/zz-repro84.spec.ts`。コミットしない）：ステージ3のコードの読み込みを `page.route` で 3 秒遅らせ、`sessionStorage` に `high` を入れて `?stage=3` を開いた。今の待ち方は 0.5〜0.8 秒で抜け、`cover` は undefined だった。今の待ち方のあとに「`__nori.cover` ができるまで待つ」を挟むと、`source` は `"memory"`、`look` は `null` で、CI の 406 行と同じ形で落ちた。直した待ち方（一覧 1）は 4.3〜4.5 秒待って、`look` が `"textured"` で通った
4. タイトルは、判定の枠の中を `START.judgePollSeconds`（0.25 秒）ごとに見に行き、判定が済んでいたら同じ見回りの中で枠を外す（`src/render/titleJudgeFrame.ts:93-109`）
5. E2 は「測っている」を待つ呼び出し（205 行）、枠を探す呼び出し（235 行）、枠の中を読む呼び出し（237 行）が別々。間に見回りが入って判定が済むと、枠が外れて 237 行が `Frame was detached` で落ちる。落ちた回の画面の記録に枠はなく、タイトルだけだった
6. ブラウザは、1 回の JavaScript の呼び出しの途中に、ほかの処理（見回りの `setInterval`）を割り込ませない。タイトルのページの 1 回の呼び出しの中で、「測っている」の確認と枠の中の読み取り（同じオリジンの `contentWindow` から）を済ませれば、読む途中で枠が外れることはない
7. 判定は測るのに約 3 秒かかる（NORI-76 の計算の節「タイトルで判定が済むまで」）。`waitForFunction` は描画ごと（`requestAnimationFrame`）に条件を見るので、遅い CI（約 0.6〜3 fps）でも、測っている間に 1 回以上見られる見込み
8. 分からないこと：E2 が PR #90 で 2 回続けて落ち、PR #92 では通った理由（機械の速さの違いと見ているが、確かめていない）。E5 がその回はステージ3だけで落ちた理由（待ちが抜けてから読むまでの間に、ちょうどステージのコードが届いた回と見ている。どのステージでも同じ形で起きうる。確かめていない）

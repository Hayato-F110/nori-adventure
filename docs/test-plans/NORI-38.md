## 調べて分かったこと（一覧の前提）

1. ページは `index.html` の1つだけ。開く URL は `/nori-adventure/`（タイトル）と `/nori-adventure/?stage=N`（`src/main.ts` が `parseRoute(location.search)` で分ける）。ステージ2〜5は `src/main.ts` から `import()` で読む（ビルドでは別のファイルになる）。ポリシーは `public/privacy.html`
2. `src/main.ts` は、タイトルとステージ2〜5の分かれ道で、終わらない `await` で止まる。登録はこの分かれ道より前で呼ぶ
3. ビルドの `base` は `/nori-adventure/`（`vite.config.ts`）。ソースマップ（`.map`）も出る（`sourcemap: true`）。CI の `check` では、単体テストが build より前に流れる（`.github/workflows/ci.yml`）ので、単体テストの時には `dist` がない
4. CSP（ページが読み込んでよい相手を決めるブラウザへの指示）は `index.html` の `<meta>` で、`default-src 'self'`・`script-src 'self' 'wasm-unsafe-eval'`。`worker-src` と `manifest-src` は書いていないので、`script-src`・`default-src` の `'self'` に従い、同じサイトの Service Worker（通信なしでもページを出すための、ブラウザの裏で動く仕組み）とマニフェストは許される。違反はコンソールのエラーに出るので、E2E のエラー 0 で見る
5. モデルは `public/models/manifest.json` を `fetch` で読んでから GLB を読む。読めなければ箱のまま遊べる作りなので、読み込みが終わるのを待ってから数える
6. `clients.claim` を呼ばないので、Service Worker を登録したページは、開き直すまでその下に入らない（`navigator.serviceWorker.controller` が null。MDN「Clients: claim()」）
7. Playwright の公式の文書に、`context.setOffline(true)` が Service Worker の中の通信を止めるかは書いていない（https://playwright.dev/docs/api/class-browsercontext の setOffline の注は「ブラウザのふつうの通信」とだけ書く）。Service Worker が出す通信は `context.route()` に見える（https://playwright.dev/docs/service-workers ）。そこで E2E は、通信を切ったあと `context.route` で全部の通信を止めて数える
8. まだ Service Worker・マニフェスト・アイコンはない。アイコンの PNG は、今ある Playwright で自作の SVG を写して作る（新しい部品を入れない）

## 調べて分かったこと（一覧の前提）

1. ページは `index.html` の1つだけ。開く URL は `/nori-adventure/`（タイトル）と `/nori-adventure/?stage=N`（`src/main.ts` が `parseRoute(location.search)` で分ける）。ステージ2〜5は `src/main.ts` から `import()` で読む（ビルドでは別のファイルになる）。ポリシーは別のページ `public/privacy.html`（`/nori-adventure/privacy.html`）
2. `src/main.ts` は、タイトルとステージ2〜5の分かれ道で、終わらない `await` で止まる。登録はこの分かれ道（`parseRoute` の行）より前で呼ぶ
3. ビルドの `base` は `/nori-adventure/`（`vite.config.ts`）。ソースマップ（`.map`）も出る（`sourcemap: true`）。CI の `check` では、単体テストが build より前に流れる（`.github/workflows/ci.yml`）ので、単体テストの時には `dist` がない
4. CSP（ページが読み込んでよい相手を決めるブラウザへの指示）は `index.html` の `<meta>` で、`default-src 'self'`・`script-src 'self' 'wasm-unsafe-eval'`。`worker-src` と `manifest-src` は書いていないので、`script-src`・`default-src` の `'self'` に従い、同じサイトの Service Worker（通信なしでもページを出すための、ブラウザの裏で動く仕組み）とマニフェストは許される。違反はコンソールのエラーに出るので、E2E のエラー 0 で見る
5. 公開の場所 `hayato-f110.github.io` は、同じアカウントのほかのページとオリジン（保存場所を分ける単位）が同じ。キャッシュは名前の頭 `nori-adventure-` で自分のものだけを扱う
6. `clients.claim` を呼ばないので、Service Worker を登録したページは、開き直すまでその下に入らない（`navigator.serviceWorker.controller` が null。MDN「Clients: claim()」）
7. Playwright の公式の文書に、`context.setOffline(true)` が Service Worker の中の通信を止めるかは書いていない（https://playwright.dev/docs/api/class-browsercontext の setOffline の注は「ブラウザのふつうの通信」とだけ書く）。Service Worker が出す通信は `context.route()`（Playwright で通信を横取りする仕組み）に見え、Service Worker がキャッシュから返した要求は `route` に来ない（https://playwright.dev/docs/service-workers ）。そこで E2E は `setOffline` を使わず、`route` で全部の通信を止めて数える。数える仕組みが働くことは、同じ E2E の中でわざと1件をキャッシュから消して確かめる
8. Playwright の `serviceWorkers` の既定は登録を許す（https://playwright.dev/docs/api/class-browser の newContext）。今ある E2E は全部ビルドを開くので、何もしないと全部が Service Worker を登録し、裏で約 7.28 MiB を読む。FPS など実際の速さの E2E に響くので、設定で `"block"` にし、`e2e/offline.spec.ts` だけ `"allow"` にする
9. Vite の公式の文書「The public Directory」（https://vite.dev/guide/assets ）は、public のファイルをルートからの絶対パス（`/icon.png`）で参照すると書く。「Public Base Path」（https://vite.dev/guide/build ）は、HTML の参照が base に合わせて書き換わると書くが、`<link rel="manifest">` まで書き換わるとは書いていない。そこで E2E はブラウザが解決したあとの `href` を見る
10. E2E の運転役（`e2e/driver.ts`）は、ステージごとに状態の形が違う。5 つのステージで使える「決まった入力を出し続ける」運転役（`stepsPerFrame` つき）を `e2e/driver.ts` に足す。読む口は、ステージ1 `state()`（刻み・`car`）、2 `train()`（刻み・`train.distance`）、3 `plane()`、4 `sub()`、5 `rover()`。ステージ2の列車は `#train-choice button[data-train=…]` で選ぶ
11. 飛行機（ステージ3）と潜水艇（ステージ4）は、入力がなくても一定の速さで前へ進む。入力が効いたことは、ステージ3は上の入力（`throttle 1`）で高さが増えること、ステージ4は下の入力（`throttle −1`）で深さが増えることで見る
12. モデルの読み込みは失敗を黙って捨てる（箱のまま遊べる）。読み終わりを読む口：全ステージ `carModel`・`look`、ステージ1 `cityLife().models`、ステージ2 `passingModel`・`landmarks().stations`、ステージ3 `skyScenery().planeModel`、ステージ4 `seaModels`。木は、読めなかったときと低画質のときが同じ値で、読み終わりを読む口がない
13. まだ Service Worker・マニフェスト・アイコンはない。アイコンの PNG は、今ある Playwright で自作の SVG を写して作る。テストで画素を読むのは `node:zlib`（Node の標準の部品）で、新しい部品を入れない

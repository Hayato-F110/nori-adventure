## 調べて分かったこと（一覧の前提）

1. PreToolUse の Hook は「`EndConversation` 以外のすべての道具の名前」に当たる。Skill の道具にも当たり、「a `PreToolUse` hook matching the `Skill` tool fires only when Claude calls the tool」「typing `/skillname` directly bypasses `PreToolUse`」（公式 https://code.claude.com/docs/en/hooks 、2026-11-17 に原文で確かめた）。そのため、オーナーが自分で `/code-review` と打てば、この Hook を通らない（例外の道。Claude が自分で 3 回目を呼ぶのだけを止める）
2. 止め方は、終了コード 2（標準エラーの文が理由として Claude に見える）か、JSON の `permissionDecision: "deny"`（同じ文書）。ほかの Hook（`review-before-pr` など）と同じく終了コード 2 を使う
3. Hook の入力の `cwd` は「the worktree root after Claude enters a worktree, and the new directory after Claude runs `cd`」（同じ文書）。会話の記録（transcript）の各行の `cwd` も、その時の場所になる。PR #94 では、同じ返答の中で `cd` で NORI-84 の作業場所に移ってから `/code-review` を呼び、`review-before-pr` が通した。前の会話で「返答を始めたときの場所で数える」と書いたのは思い違いだった（今の数え方は正しい。一覧 4 で回帰のテストにする）
4. 会話の記録はセッションごとのファイル（`~/.claude/projects/<プロジェクト>/<セッション>.jsonl`）。会話がまとめられ（compact）ても、同じセッションなら同じファイルに続く。日をまたいで新しいセッションにすると、別のファイルになる。今の `review-before-pr` は自分のセッションのファイルだけを読むので、前のセッションで呼んだ回は数えない。回数を数えるときは、同じフォルダの全部の `.jsonl` を読む必要がある
5. 記録のフォルダの大きさ（2026-11-17 に測った）：12 ファイル・249 MB。直近 3 日に変わったものは 4 ファイル・88 MB。いちばん大きいファイルは 47 MB
6. スキルの呼び出しは、記録の `tool_use` で `name` が `Skill`、`input.skill` が `code-review`（プラグインのスキルは `名前:code-review`）。成功したかは、同じ `id` の `tool_result` の `is_error` で分かる（`review-before-pr.mjs` の `isReview` と `reviewDecision` と同じ）
7. ブランチごとに数えるため、「その場所（作業場所の根）で、そのブランチが main から分かれた時刻（`git merge-base origin/main HEAD` のコミットの時刻）より後に成功した `code-review`」を数える。同じ名前の作業場所を、あとで別のブランチに使っても、分かれた時刻で前の回を外せる
8. 回数を Git の設定やファイルに書いて数える案は採らない。Claude がコマンドで書き換えられるため。会話の記録は Claude の道具では書き換えない
9. main（PR のブランチでない場所）で呼ぶ `/code-review` は止めない（PR の決まりの外）

# NORI-73 テストの一覧（ステージ2の見た目の E2E を、駅まで早送りで走らせる）

- 2026-11-15：案を書いた
- もとの課題：CI でたまに落ちる E2E（実際の時間に頼るもの）。2026-11-15 に、`e2e/stage2.spec.ts:151`「ステージ2の見た目（低画質）：駅の旗が土手より目立つ」が、文書だけの PR #79 と Hook だけの PR #80 の CI で、上限 150 秒をこえて2回落ちた（Jira のコメント 10119・10120・10121）
- 問題：`checkLook` は、1つ目の駅まで走る運転役を早送りなし（`stepsPerFrame` なし）で入れている。ゲームを進める部分が実際の時間に頼っていて、遅い CI では時間が足りない
- 直し方：CLAUDE.md「E2E は2種類に分ける」の、ゲームを進めて結果を確かめる種類にする。駅まで走る運転役を早送りで入れる。明るさは止まったあとの画面で測るので、測る値と比の下限（`LOOK.minStarContrast` 3）は変えない
- この一覧は、課題の「起きたこと 2」（ステージ2）だけを扱う。「起きたこと 1」（プライバシーのページの全画面の撮影）は原因の調べが先なので、別の一覧で扱う（刈り取り）
- 一覧を変えるときは、この表を直して初見レビューを回し直し、オーナーの承認をもらう

## 調べて分かったこと（一覧の前提）

1. 早送りしないとき、1 コマに進める刻みは最大 5（`SIM.maxStepsPerFrame`、`src/core/loop.ts:19-25`）。ゲームの進む速さ ＝ 実際の時間 × min(1, 5 × FPS ÷ 60)。CI が 12 fps より遅いと、ゲームは実際より遅く進む
2. 早送りの刻みの数は、毎コマ `__noriDriver.stepsPerFrame` から読む（`src/input/testDriver.ts:38-43`）。1 コマの上限の刻みの数は、ステージを作ったときに決まる（`createFixedStepper(…, fastForward(…)?.maxSteps ?? …)`）。そのため、早送りは `page.goto` の前に運転役を入れたときから効く（途中で切り替えない）
3. 同じファイルのほかのテスト（`stage2.spec.ts:79`・`:131`）は、同じ運転役を `FAST`（20）で入れて、1つ目の駅まで走っている
4. 「低画質」の版は、CPU を 20 倍遅くして、画質が自動で低に下がるのを待つ（上限 90 秒）。この間も列車は走る（列車を選んだあとなので）。画質の判定は実際の FPS で行い、ゲームの刻みとは関係ない
5. 明るさは、止まってからカメラが追いつく 90 刻みのあとの画面で測る（`stage2.spec.ts:178-198`）。早送りでも、止まったあとの刻みは同じ運転役（入力 0）で進むので、測る画面の位置は変わらない

# 脅威分析（STRIDE）

> NORI-35。最終更新：2026-11-05。完了条件：**各脅威に対策と確認方法がある**。
> 重大度：高＝大事なファイル・個人の情報が外に出る、子どもに害がある／中＝作業が壊れる・やり直しが要る／低＝不便。
> 状態：済み＝入っていて確かめた／手順あり＝作業待ち／未実施＝課題キーの作業で入れる／受け入れる＝残るリスクとして認める。
> 新しい道具・サービス・データの流れを足すときは、この表に行を足してから使う。

## 守るもの（資産）

| ID  | 資産                                                    | 置き場所                                       |
| --- | ------------------------------------------------------- | ---------------------------------------------- |
| A1  | オーナーの個人のファイル（書類・写真・家族のデータ）    | オーナーのユーザーフォルダ、`G:\` など         |
| A2  | 秘密情報（GitHub の認証、SSH の鍵、環境変数のファイル） | オーナーのユーザーフォルダ                     |
| A3  | リポジトリ（ソース・履歴）                              | オーナーのユーザーフォルダ、GitHub（公開予定） |

| A5  | 遊ぶ子どもと家族（安全、プライバシー）                  | 公開サイト（GitHub Pages）を開くブラウザ       |
| A6  | 人の名前（オーナーの姓名など）                          | リポジトリの文書・コミット、Jira               |

## データの流れ

```
オーナー ─ Claude Code ─┬─ リポジトリ ─ GitHub（CI・Pages）─ 子どものブラウザ
                        ├─ Blender MCP ─ Blender（noriblender） ─ C:\NoriBlender\
                        ├─ Jira の MCP（作成・更新）
                        └─ Web 検索・取得（公式ドキュメント）
自作モデルの画像 ─ AI 動画サービス（NORI-40。契約はオーナー）
```

## ISO/SAE 21434 との対応（参考）

- 資産と脅威の表は TARA（脅威分析とリスク評価）の「資産の特定」「脅威シナリオ」にあたる。重大度は簡単な影響の評価
- 対策は「サイバーセキュリティの管理策」、確認方法は「検証」にあたる。状態が「未実施」の行は、課題キーの作業で埋める
- 「受け入れる」の行は、リスクの受容（理由を表に書く）

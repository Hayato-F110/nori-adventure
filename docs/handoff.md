**つまずき防止**

- 時刻・日付を書く前に、毎回 `date` を見る（止める Hook は NORI-100（バックログ））
- Git Bash で `git show origin/main:<パス>` を書くと、パスが Windows の形に書き換えられて失敗する。`MSYS_NO_PATHCONV=1` を付ける（11/23）
- フォルダの大きさを `du` で測ると、作業場所の中の `node_modules` のつなぎ（ジャンクション）をたどって何度も数え、5 分で終わらなかった。つなぎをたどらない測り方（`FileAttributes.ReparsePoint` を飛ばす）で 1 分ほど（11/23）
- Claude はリポジトリを削除できない（権限の設定で止まる）。削除はオーナーが流す
- PR を出したら、CI を待たずに次の課題を進める。PR の前に `gh pr view --json mergeable` でぶつかりがないかを見る
- CI の見張りは PR ごとに 1 つ。流し直したら、前の見張りを止めてから新しく作る
- CI の e2e が 25 分の上限で取り消されると、Playwright の報告が残らない。落ちたテストの数をログの全文で見てから、`gh run rerun <id> --failed` で落ちた job だけを流し直す（NORI-98）
- PR の説明・リポジトリに Jira のサイトのアドレスを書かない。課題キーだけにする
- 刈り取りの表の「結果」に「まだ」という言葉を、済んだ行の中でも使わない（Hook `harvest-before-done` が未達と読む。NORI-97）
- 手元の E2E を流す前に、4173 番が空いていることを確かめる。バックグラウンドの作業を止めたら、本当に止まったかを見る
- E2E の赤を確かめるためにわざと壊すときは、型の検査を通る壊し方にする
- レビューのあとに直しを足したら、PR に直しごとの証拠の表を書く。Hook `review-before-pr` はまだ止めるので、直しのコミットだけを `/code-review low` で回す（NORI-83 で直す）

- Jira の遷移は `transitionId`（進行中 21・完了 31）で指定する。遷移と一緒に開始日の欄は入れられない（別に `editJiraIssue` で入れる）

変更をレビューしてください。対象：$ARGUMENTS（指定がなければ `git diff` と `git diff --staged`。変更がなければ main との差分 `git diff main...HEAD`）

次の順で報告する。

1. **良い点**（具体的に。なぜ良いのかも）
2. **直すべき点**（重要な順。各項目に「ファイル名:行番号」「理由」「直し方」）
3. **プロジェクトのルールとの照合**
   - `src/core/` が Three.js・DOM・`Math.random`・`Date.now`・`performance.now` に依存していないか。固定刻みで、同じ入力 → 同じ結果か
   - ゲームの数値が `src/config/` にあり、`docs/game-rules.md` と一致しているか（コードへの直書きがないか）
   - 隠れた補正（順位調整・確率操作・見えないハンドル補正）が入っていないか。補助なら `ASSIST` でオン・オフでき、初期値がオフか
   - 失敗の罰が強くないか（最初に戻さず、その場からやり直せるか）
   - 子ども向け UI：文字に頼らない、ボタン 64px 以上、音量控えめ・ミュート、外部通信・広告なし
   - テストが先に書かれ、完了条件を確かめているか。E2E・スクリーンショット・FPS・コンソールエラーを確かめたか
4. **安全**：秘密情報、人の名前、家族の写真・声・顔、外部への通信、CSP の変更、依存の版（`save-exact` で固定か、公式の変更履歴・セキュリティ情報を確かめたか）
5. **学びのポイント**を1つ（C言語・車載ソフト開発との比較で、短く）

指摘は読んで確かめた事実に基づき、推測はその旨を書く。指摘がなければ無理に作らない。コードは変更しない。
UI の細かい確認は `kids-ui-reviewer`、公開・秘密情報の確認は `privacy-reviewer` のサブエージェントに任せてもよい。

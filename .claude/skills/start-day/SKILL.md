1日の作業を始めます。次の順で進めてください。

1. `date` で今日の日付と時刻を確かめる（記憶や推測で書かない）
2. 読む：`docs/handoff.md`（最初に）、`CLAUDE.md`、最新の `docs/devlog/YYYY-MM-DD.md`、`docs/schedule.md`（スプリントの全体の表。今のスプリントの課題は手順 4 で Jira から読む）
3. `git status`・`git branch -a`・`gh pr list` で、作業中のブランチと未マージの PR を確かめる。あわせて `node tools/dev/agent-reports.mjs` で、48 時間の中に自動で保存したサブエージェントの報告（`.claude/agent-reports/`）を一覧にし、引き継ぎに「受け取れていない」「回し直す」とある報告がそこにないかを先に確かめる（2026-11-15。前のセッションの報告を探さずに「残っていない」と判断したため）
4. Jira（NORI）で、今のスプリントの課題の状態を確かめる（`searchJiraIssuesUsingJql`、`project = NORI AND sprint in openSprints()`）。引き継ぎと違う点があれば知らせる。あわせて、スプリントの始まり・終わりの日時を Jira から読む（`executeRead` の `listJiraBoardSprints`、ボード 35、`state: "all"`。UTC なので +9 時間して書く）。引き継ぎ・`docs/schedule.md` の日付は古いことがあるので、残り日数には使わない（2026-11-17。スプリント3を 11/18 まで延ばしたのに、引き継ぎの古い表の「11/17 23:00」を書いたため）。あわせて、今のスプリントの課題の Jira のコメント（`listJiraIssueComments`）から「オーナーが決めた」ものを課題ごとに一覧にし、`docs/handoff.md` の「オーナーが決めたこと」の節（なければ作る）に写す。勧めたり進め方を決めたりする前に、その一覧を読み直す（2026-11-21、スプリント4のふりかえりの改善 I2。オーナーが自分で見つけた K33-10〜12 の後回しを、11/20 の決定（直していない版を家族に見せない）を読み直さずに勧めたため）
5. 次を簡潔に示す
   - 今日のゴール（1〜2行）と、スプリントの残り日数（手順 4 で Jira から読んだ終わりの日時から数える）
   - 作業の順番（課題キー・完了条件・目安時間）
   - 今日オーナーにお願いすること（画面での操作、承認が要ること、お金や外部サービスに関わること）。最初にまとめて伝える
   - 人の作業（家族のテスト・実機の確かめ・画面での確かめ）の予定の日がスプリントの最終日なら、そう知らせ、前の日へ動かす案をおすすめと理由つきで出す（`docs/schedule.md` の決まり。スプリント4のふりかえりの改善 I1）
   - 遅れがあれば、削る候補（スプリントの範囲の変更はオーナーの承認が要る）
   - **今日学ぶこと**：「流行の技術」「Claude の使い方」「セキュリティ」の3つに分けて、それぞれ1〜3行。今日の作業で実際に使うものだけを書き、仕事（車載ソフト開発）のどこで使えるかを添える。セキュリティは ISO/SAE 21434・TARA との対応を一言
   - **今日出てくる用語**（表。列は「用語｜略称｜読み方｜一言の意味」。前の devlog で説明済みのものは除く）
     - 略称：略語ならもとの正式な名前（例：PWA → Progressive Web App）。略語でなければ「—」
     - 読み方：カタカナで（例：Rapier → レイピア、`git cherry` → ギット チェリー）。公式の読み方があればそれに合わせ、分からなければ「（一般的な読み）」と添える
6. 引数が「確認だけ」なら、ここで止める。それ以外は、CLAUDE.md の進め方に沿って最初の作業に入る（作業を始めた課題は Jira で「進行中」にする）

name: commit
description: 変更を確かめ、課題キー（NORI-xx）付きのメッセージでコミットする。秘密情報・個人名・スクリーンショットの混入を確かめる
disable-model-invocation: true
argument-hint: "[課題キー 例: NORI-13]"
---

コミットします。課題キー：$ARGUMENTS

1. `git status`、`git diff`、`git diff --staged` で変更を確かめる
2. コミットの前に確かめる（1つでも当てはまれば止めて知らせる）
   - main の上にいないか（いれば `feature/NORI-xx-短い説明` のブランチを作る）
   - 秘密情報（環境変数のファイル、鍵、トークン）が入っていないか
   - 人の名前（作業者の姓名など。「オーナー」と書く）、家族の写真・声・顔が入っていないか
   - `screenshots/`、`test-results/`、`blender-work/` のファイルが入っていないか
   - 関係のない変更が混ざっていないか（混ざっていれば、コミットを分ける）
3. `npm run check` を実行し、通ることを確かめる（落ちたら直してから）
4. メッセージ：`NORI-xx 要約`（日本語。課題キーがなければブランチ名から読み取る。Jira に取り込む前の作業は `NORI-TBD`）。必要なら本文に「なぜ」を1〜3行。最後に、システムの指示にある Co-Authored-By の行を付ける
5. ファイルを名前で指定して `git add` し（`git add -A` は使わない）、コミットする。結果（コミットの ID と要約）を報告する

push と PR 作成は、このスキルでは行わない（必要なら続けて行う）。

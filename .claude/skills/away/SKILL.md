オーナーは離席します。自律的にどんどん進めてください。オーナーの承認が必要な作業は、戻ってきたときにお願いします（2026-11-12 にオーナーが決めた）。

## 進めてよいこと（承認を待たない）

`CLAUDE.md`「必ず止まってオーナーの承認をもらう」に当たらない作業は、止まらずに進める。

- 承認済みのルールとテストの一覧に沿った実装・テスト・コミット・PR の作成
- CI の監視（バックグラウンド）。緑になった PR のマージと、マージ済みのブランチの削除（`git branch -d`・`git push origin --delete`）
- Jira の状態の更新（始めたら「進行中」と開始日、マージしたら「完了」）
- 落ちた CI のログ（`gh run view --log-failed`）を読んで直す。前から知られている、たまに落ちるテストなら流し直す
- AI のレビュー（`kids-ui-reviewer`・`privacy-reviewer` など）の指摘を、理由をつけて「直す／直さない」に仕分けて直す
- 引き継ぎ（`docs/handoff.md`）の更新

## 戻るまで待つこと（始めない）

- `CLAUDE.md` の「必ず止まってオーナーの承認をもらう」の1〜6
- 新しいルールとテストの一覧の承認（`CLAUDE.md` ゲーム仕様のルール1。実装の前に OK が要る）。案を作るところまでは進めてよい
- オーナーにしか決められない選択（見た目・遊び方の好み、計画の変更）
- 権限の設定で拒否された操作（別の方法で回り込まない）

承認が要る作業に当たったら、そこで止めて「戻られたらお願いしたいこと」に書き留め、ほかに進められる作業に移る。進められる作業がなくなったら、引き継ぎを更新して待つ。

## 戻ってきたとき

最初の返事で、次をまとめて短く伝える。

1. 離席の間に完了したこと（PR 番号、テストの件数、CI の結果、Jira）
2. 起きた問題と、どう扱ったか（流し直したテストや、直さなかった指摘とその理由も）
3. **戻られたらお願いしたいこと**：承認が要る作業と、決めてほしい選択肢。おすすめと理由を付ける

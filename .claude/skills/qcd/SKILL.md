このセッションでの Claude Code の使い方を振り返ってください。一般論ではなく、この会話の事実に基づくこと。

1. 次の観点で事実を拾う
   - **Q（品質）**：完了条件とテストを先に書いたか、Playwright で画面・FPS・コンソールエラーを確かめたか、変更は小さかったか（1つの PR に1つの課題か）、AI の指摘を理由つきで仕分けたか
   - **C（コスト）**：手戻りや指示の出し直しはあったか、`/clear`・`/compact` を使うべき切れ目はあったか、同じ指示を繰り返していないか（スキルにできるか）、推測で進めて失敗していないか
   - **D（スピード）**：並列にできた作業、バックグラウンド実行、worktree、オーナーを待たずに進められた課題はあったか
2. 良かった点を1つ
3. 改善点を **3つ以内**。各項目は「いつ・何を・どう変えるか」を1〜2行で、次のセッションですぐ試せる形にする
4. 仕事（車載ソフト開発）に持ち帰れるものを1つ。会社のセキュリティ規程や機密コードの扱いに注意が要るときは一言添える

`/context` と `/usage` はオーナーが実行する組み込みコマンドなので、結果があると正確になることを伝える。

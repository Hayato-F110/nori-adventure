1日の作業を終えます。次の順で進めてください。

1. `date` で日付と時刻を確かめる。日付は 0 時で区切らず、`/end-day` を実行するまでを同じ日として扱う
2. 今日の作業を把握する：前回の devlog を最後に変えたコミット（`git log -1 --format=%H -- docs/devlog`）から先の `git log --oneline`、`gh pr list --state all --limit 20`、`git status`、この会話の内容
3. `docs/devlog/YYYY-MM-DD.md` に追記する（なければ作る。見出しは既存の devlog に合わせる）
   - **やったこと**：課題キー・PR 番号・検証の結果（テスト件数、FPS、コンソールエラー）を事実で
   - **失敗**：何が起き、実際の値・ログで何が分かり、どう直したか
   - **学び**：次に同じことをするとき何を変えるか。仕事（車載ソフト開発）に持ち帰れるものがあれば添える
4. `docs/handoff.md` を書き直す（次のセッションが最初に読む）：いまの状態、作業中のブランチと PR、明日の作業順、つまずき防止のメモ、オーナーにお願いすること。最終更新の時刻を `date` の値で書く
5. Jira：今日作業した課題の状態をそろえる（`transitionJiraIssue`。11＝未着手、21＝進行中、31＝完了）。完了にするのは、PR をマージして完了条件を確かめたものだけ
6. コミットしていない変更を、作業ブランチ（なければ `feature/NORI-10-devlog-YYYY-MM-DD`）でコミットし、PR を作る。CI が緑ならマージする
7. 会話に、次を出力する
   - **今日学んだこと**（表）：「流行の技術」「Claude の使い方」「セキュリティ」の3つに分けて、それぞれ2〜4行。実際に今日使ったもの・起きたことだけを書き、仕事（車載ソフト開発）での使いどころを添える。セキュリティは ISO/SAE 21434・TARA との対応を一言
   - **学んだこと3行**の下書き（devlog の「学び」から選ぶ）。オーナーが自分の言葉で直せるように示し、直したら devlog にも反映する
   - 今日の進捗（計画どおり／遅れ：何が・どれくらい）と、明日の最初の作業を3行で

devlog と handoff には、人の名前（「オーナー」と書く）、家族の写真・声・顔、秘密情報を書かない。
